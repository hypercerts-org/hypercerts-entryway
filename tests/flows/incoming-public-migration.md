# Test an independent account moving into Entryway

Contributors: run `./tests/local.sh fresh-group incoming-public-journey` for a disposable Atmosphere in a Box project. After `prepare` and `up` in an owned project, use `./tests/local.sh incoming-public-journey` instead. See the [testing guide](../../docs/testing.md#public-incoming-journey) for setup and cleanup.

1. Create an account on the standalone stock source PDS, upload a blob and write a profile referencing it. Keep the source session for cutover checks.
2. Verify a distinct destination email with OTP. Present a fresh code, the source DID and destination handle on the incoming page. Save the one-time arrival code, exact handoff and prepared endpoint. Destination email proof does not establish source authority.
3. Request PLC confirmation from the source and sign the prepared operation using its emailed token. Submit it to Entryway with a method-bound source service JWT and the `Entryway-Arrival-Code` header. Read the PLC head before creation: it must equal the signed operation, including the signature. If the move is abandoned here, Entryway's rotation key stays on the DID until removed. Arrival expiry does not remove it.
4. Mint a separate source service JWT for `createAccount`. Present the arrival header, destination handle, password and recovery key. If the deployment requires an invitation, an administrator issues it separately; the migrant supplies the code, not administrator credentials. Check that the returned DID matches the source and the destination is paused.
5. Export the CAR and fetch blobs from the source. Import and upload directly to the prepared destination using tracked credentials. Refresh at Entryway, then request activation through the stock destination. Confirm activation and read the chosen record and blob there. Check the PLC endpoint, handle and ordered rotation keys before deactivating the source. The client chooses when to cut over; this tests neither an exhaustive inventory nor writes made after export.
6. Try a write and refresh on the deactivated source with the original credentials: expect 401 and 400 respectively. Check that the destination family can now refresh as an ordinary session.
7. In a fresh browser context, sign in with destination email OTP and check the source DID. Authorize the independent browser SDK by destination handle with visible consent. Check the issuer, make a DPoP write and follow the SDK's audience-derived readback link to the prepared PDS. Reload, require a successful token refresh, then write and read back again. Revoke that client session. Separately authorize the confidential test client and check its subject, audience and write.

This journey uses the repository's public-endpoint client, not private fixture calls. The [synthetic migration](external-migration.md) exercises restart boundaries; it is not evidence for the public flow.
